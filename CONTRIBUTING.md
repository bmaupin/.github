# How to contribute

Thanks for your interest in contributing to this project.

#### Guidelines

These will increase the likelihood that a given pull request will be accepted:

- **Please try to limit each pull request to one change.** This makes it much easier to review and merge; small pull requests are fine :)
- [Don’t be clever](https://www.simplethread.com/dont-be-clever/); simple solutions that are easy to understand are preferred over solutions that need comments to explain and use the latest whizbang language features
- If the project has tests, please make sure that they pass
- If the project has tests and you're adding new features, please add new tests to cover them
- Please try to avoid making breaking changes to libraries or APIs; it's generally preferable to add a new method for a new feature rather than modify an existing one
- Please document any newly-added public methods/endpoints
- Please try to match existing code style as best as possible
  - Check the project to see if it uses a formatter or use the de-facto formatter for a particular language, e.g. [Prettier](https://prettier.io/), `rustfmt`, etc.
- [Conventional Commits](https://www.conventionalcommits.org) are nice although not a requirement
- AI-generated pull requests may be accepted for consideration, with additional stipulations
  - The above guidelines must be more strictly adhered to
  - The code should be reviewed and understood by the submitter first
  - Pull requests must be small in size and scope in order to facilitate human review
  - AI-written code may be accepted but AI-generated writing and documentation is not accepted

Cheers!
